# Inventario de producto: Lazunox 0.5.36 (2026-10-17)

Auditoría de solo lectura sobre `/Users/ben/Documents/App OpenCode` (rama `main`, commit `a5f5d503`). Todo lo de abajo sale del código, de `AGENTS.md`, `README.md`, `CHANGELOG.md` y `docs/`. No se ejecutó la app ni se leyeron credenciales.

**Qué es:** cliente de escritorio Electron/React que arranca un servidor OpenCode local (`opencode serve`, versión fijada en `resources/opencode-bin/pin.json`, hoy 1.19.0) y habla con él por el SDK. Cuatro modos: **Chat**, **Code**, **Overdrive** (en el código `tasks`) y **Rutinas**. Sin cuentas ni servidor propio. Proyecto "independiente y sin fines de lucro" para promover OpenCode Go.

**Leyenda de madurez:** `completa` = implementada de punta a punta y con uso real documentado; `parcial` = existe pero con huecos declarados; `experimental` = beta, apagada por defecto o sin probar en equipo real; `diseño` = solo plan o código inerte.

**Leyenda de pruebas:** `U` = pruebas unitarias Vitest (hay 598 archivos `*.test.ts(x)` en `src`); `E2E` = spec Playwright/Electron con OpenCode falso (50 specs en `e2e/specs`); `Py` = pruebas Python de las skills (12 archivos); `Manual` = checklist humana pendiente según `docs/VERIFICACION.md`. Ojo: `docs/VERIFICACION.md` dice que casi todo está "Solo pruebas automáticas" (nadie lo ha usado a mano con modelo y datos reales según su tabla de la 0.5.9; esa tabla no se ha vuelto a fechar).

**Plataformas:** Mac = macOS Apple Silicon arm64 (no hay build Intel). Win = Windows 10/11 x64 (instalador NSIS sin firmar). Las capacidades por plataforma las decide `src/shared/platform-caps.ts`.

# Lo que NO existe (y es razonable esperar en una app así)

Verificado con búsquedas en `src`, `resources` y `docs`. "No existe" = no hay ni código ni UI; "parcial" lo indico.

1. **Memoria automática entre conversaciones en Chat.** Solo hay memoria con aprobación manual, y el alcance por proyecto existe solo en Overdrive. El plan maestro dice textualmente que "web+memoria Chat" queda fuera de alcance.
2. **Projects con archivos de conocimiento** (subir documentos a un proyecto y que el modelo los consulte en cada chat). Lo más cercano: Overdrive trabaja sobre una carpeta, tiene instrucciones y `AGENTS.md` por carpeta; Chat no tiene proyectos.
3. **Conectores de correo, calendario, Drive/Docs, mensajería** integrados o de un clic. El catálogo trae 7 fichas, todas de desarrollo (context7, cloudflare-docs, github, linear, notion, sentry, atlassian). Cualquier otro hay que añadirlo a mano como MCP.
4. **Disparadores por evento en Rutinas** (archivo nuevo, correo, webhook, commit). Solo reloj: diario, semanal, cada N horas, cron. No recupera ejecuciones perdidas con la app cerrada.
5. **Tareas/agentes en la nube.** Todo corre en el equipo del usuario y con la app abierta; no hay ejecución remota ni "continuar en la nube".
6. **Generación de imágenes** (ni herramienta, ni UI, ni skill). Solo hay gráficos nativos en Excel/PowerPoint e imágenes de bancos de fotos incrustadas en documentos.
7. **Compartir o exportar conversaciones.** El motor tiene `share: "disabled"`. No hay exportar en Chat ni en Code; solo "Exportar a Markdown" en Overdrive. No hay colaboración multiusuario, comentarios ni espacios de equipo.
8. **Extensión de navegador / control del navegador del usuario.** Solo el navegador integrado de la app (con MCP propio).
9. **Voz conversacional.** El dictado es solo español, graba y luego transcribe; no hay lectura en voz alta de respuestas ni modo de conversación hablada.
10. **Revisión de código automática y flujo de PR** (crear rama, push, abrir pull request, revisar un PR). Code hace commit local y diff, nada más. No hay integración con GitHub/GitLab (salvo el MCP de github del catálogo).
11. **Búsqueda global en el historial** de Chat y Code por contenido. Solo por título (Chat/Code) y por contenido dentro de una carpeta de Overdrive.
12. **Cuentas, sincronización entre dispositivos e historial en la nube.** Decisión de diseño: no hay cuentas. El historial vive en el equipo.
13. **Instrucciones personalizadas globales para Chat y Code** desde la UI (solo Overdrive las tiene; en Code se depende de `AGENTS.md` que lee OpenCode).
14. **Artifacts interactivos** (apps/HTML con ejecución y publicación). Hay vista previa de HTML y presentaciones, no un espacio de artefactos persistentes ni publicables (el plan maestro lo lista como fuera de alcance).
15. **Adjuntar Word/Excel/PowerPoint al modelo en Chat**, ni uso de hojas de cálculo como contexto en Chat. Se aceptan imágenes, PDF y texto.
16. **Mac Intel, Linux y móvil nativo.** Solo Mac arm64 y Windows x64; el celular es una PWA experimental.
17. **Firma y notarización** (Developer ID / Authenticode) y **política de privacidad publicada**.
18. **Plugins/extensiones y marketplace de skills** de la app. Las skills incluidas son 6; el usuario puede proponerlas desde el agente, pero no hay galería ni instalación desde catálogo.

## Las 10 ausencias más relevantes frente a Claude y ChatGPT

1. Memoria automática entre conversaciones (y memoria de Chat en general).
2. Projects con archivos de conocimiento.
3. Conectores de correo/calendario/Drive.
4. Compartir o exportar conversaciones, y colaboración.
5. Voz conversacional y dictado en otros idiomas.
6. Generación de imágenes.
7. Tareas/rutinas en la nube y disparadores por evento.
8. Extensión de navegador (control del navegador real del usuario).
9. Artifacts interactivos publicables.
10. Flujo de PR/revisión de código y búsqueda global del historial.
