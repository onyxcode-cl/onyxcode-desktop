## 6.7 - Pf1: debounce y filtro de `fsVersion` en Code (`lib/debounce.ts`)

- **Pf1 (cambio declarado)**: `session.diff`, `file.edited` y `file.watcher.updated` subían `fsVersion` en cada evento y de CUALQUIER directorio, lo que disparaba `git status` + diff (ChangesPanel) y la relectura del archivo (FilesPanel/CodeWorkspace) cientos de veces por segundo durante un `npm install` o un build. Ahora (1) solo cuentan si el directorio del sobre es el del proyecto o el de una sesión del proyecto (worktrees; comparación sin barra final) y (2) el incremento pasa por `debounce` puro (`lib/debounce.ts`: 400 ms tras el último evento, máximo 2 s de espera, así una ráfaga continua refresca al menos cada 2 s). `touchFs()`, revert/unrevert y el fin de una ejecución (`session.status` a idle, `session.idle`) siguen inmediatos. El timer pendiente se cancela al soltar la última referencia de `ensureCodeSubscription`. No se implementó "no refrescar paneles ocultos" (queda fuera de esta subfase).
- Tests: `lib/debounce.test.ts`; `features/code/impl/store.characterization.test.ts` > "eventos de archivos" (caso Pf1 invertido: otro directorio no sube; el caso `session.diff`/`file.edited` ahora avanza 400 ms con timers falsos porque el incremento es diferido) y "debounce y filtro de fsVersion (Pf1)" (100 eventos en 300 ms = 1; otro directorio = 0; worktree cuenta; ráfaga de 5 s >= 2; touchFs y revert/unrevert inmediatos; cancelación al desuscribir). Snapshots de `traces.replay` sin cambios.
- Pendiente manual: `npm install` en un proyecto con el panel Cambios visible (una sola actualización por ráfaga, cada <= 2 s).
